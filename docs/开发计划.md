# WHAT-TO-EAT-AGENT 开发计划

**依据文档**：`[docs/项目说明.md](项目说明.md)`（SRS v1.7）· `[docs/规格设计.md](规格设计.md)`（技术规格，实现以此对齐）

**计划用途**：按**开发板块**与板块内**功能**拆解任务，跟踪进度与验收；需求编号（FR/NFR/IR）与**规格章节**双引用。

**状态说明**：`待开始` → `进行中` → `已完成`；阻塞时在备注标明依赖解除条件。

## 1 里程碑与阶段定义


| 阶段           | 目标                                                               | 与需求 / 规格对应                                                    |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------- |
| **M0 基线**    | 测试夹具、现状快照用例，防止无序重构引入回归                                           | NFR-05；规格 §10                                                 |
| **M1 编排与意图** | 按需分流、`task_stack`、澄清与多意图；**意图槽位模型**；**方案 A 状态切片落地起步**            | FR-01～05，§6.1，S-05～S-06；**规格 §1.2.0～1.2.1、§1.3、§11**          |
| **M2 记忆与偏好** | L1～L4 时序、摘要与业务状态解耦；**有效约束 C**                                    | FR-10～19，S-01；**规格 §3、§4**                                    |
| **M3 菜谱检索**  | MCP 双阶段、约束 C、歧义、**R** 稳定、硬过滤                                     | FR-20～24，S-02，S-06；**规格 §2、§5**                               |
| **M4 库存与清单** | **SCOPE_ID / 表迁移**、`inventory_snapshot` **字典型 I**、补货/扣减、缺口缓存与编辑层 | FR-30～32，FR-40～43，S-03、S-04、S-08；**规格 §1.2.0～1.2.1、§6～§7、§8** |
| **M5 回复与降级** | 可解释回复、**错误码话术**、全链路降级                                            | FR-60～61；**规格 §9**                                            |
| **M6 工程化**   | 配置统一、可观测、契约测试、阶段 A/B/C 验收                                        | NFR-01～07，IR-01～05；规格 §8、§10～§11                              |


**推荐顺序**：M0 → M1 →（M2 与 M3 可部分并行）→ M4 → M5 → M6。

## 2 按开发板块与功能的任务分解

以下每个 **板块** 下按 **功能** 列任务要点；「对应」列同时指向 SRS 与**规格设计**章节。

### 板块一：编排与工作流（LangGraph）


| 功能      | 任务要点                                                     | 对应                   |
| ------- | -------------------------------------------------------- | -------------------- |
| 按需分流    | 禁止固定「检索→库存→清单」；入口意图分流仅启用必要节点                             | SRS §6.1；规格 §1.3 步 4 |
| 运行时序补全  | 在 **R、I 就绪** 后插入**静默缺口预计算**（规格 §1.3 步 5），与 logistics 边一致 | 规格 §1.3、§7.1         |
| 路由与任务语义 | `task_stack` 与 FR-04 消费语义一致；执行即出队，避免死循环                  | FR-04；规格 §11.4       |
| 澄清续跑    | `TASK_CLARIFY` 与**选菜澄清**；摘要节点不误清业务现场                     | FR-14，FR-16          |
| 文档与注释对齐 | 节点顺序、并行策略与代码一致                                           | NFR-04               |


### 板块二：Agent 状态与数据模型


| 功能                | 任务要点                                                                                                                                                                       | 对应                         |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 方案 A 顶层结构         | `AgentState` 一级键：`dialog_state`、`memory_state`、`control_state`、`recipe_state`、`inventory_state`、`response_state`、`error_state`；窄顶层仅 `active_user_id`                       | **规格 §1.2.0**；SRS §7.2.1   |
| `inventory_state` | `inventory_snapshot`：`**Dict[str, {"amount": float, "unit": str}]`**；及 `cached_shopping_gap`、`gap_basis`、`shopping_list_overlay`、`recipe_use_confirmed`、`commit_`*、`add_`* | **规格 §1.2.1**              |
| 其余六切片字段落地         | `recipe_state` 承接原 `logistics_buffer` 菜谱侧字段；`control_state` 承接 `task_stack`、`slots`、`missing_slots`、`confidence`；`memory_state` 承接 L2/L3 等；`error_state` 承接 §9             | **规格 §1.2.0**              |

> - 尚无测试用例或未进入验证：`待开始`；验证排期中：`待测试`。
> - **不适用**：该任务无单测或无可执行验收项（测试列可标不适用）。
